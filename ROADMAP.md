## Ориентиры для следующих сеансов

Проверено на 2026-09-27, коммит `3432e31`.

**Ветка и пуши.** Работаем в `refactor/split-modules`. `main` — это исходная
загрузка одним файлом, трогать нельзя. Релиз 0.4.0 уже влит в `main` на
GitHub (merge commit `6bc627f`), но локальный `main` не обновляем: разработка
в ветке, мерж — через PR на сайте. Ничего не пушим без явной просьбы.

**Сборка.** `cargo build --release && cp -f target/release/wyvern ./wyvern`.
Бинарник `wyvern` в корне отслеживается git, и без `cp -f` пользователь
запустит старый код. Версия видна в заголовке окна.

**Тесты и замеры.**

```bash
cargo test --release                                        # 44 теста
cargo test --release -- --ignored --nocapture memcheck       # замер памяти
```

Замер считает живые байты и аллокации по фазам (пол, разбор, кэш, отрисовка),
RSS берёт из `/proc/self/status`. Сравнивать числа можно только на том же
измеряющем коде: для базы есть worktree `/tmp/opencode/wyvern-base` на `9222822`
(если `/tmp` очистили — пересоздать `git worktree add /tmp/opencode/wyvern-base 9222822`),
в него копируется `src/memcheck.rs` и патчится обёртка разбора истории
(`/tmp/opencode/prep_memcheck.sh`). Свою копию измерялки правим только в
`/tmp/opencode/memcheck.rs`, в дерево копируем.

**Правила, которые не стоит нарушать.**

- Токен и пароль хранилища в чат не выкладывать никогда.
- Не запускать тесты, пишущие в `$HOME`: путь хранилища переопределяется в
  `App` (`vault_path_override`), для ручных запусков — переменная
  `WYVERN_ACCOUNTS_PATH`.
- Перед крупным шагом — бэкап в `~/Wyvern-backup-ГГГГММДД-ЧЧММ` (копия
  рабочего дерева, бинарника и `ЧТО-ТУТ.txt`; файл хранилища не копируем).
- Мелкие правки сразу коммитить в ветку: история уже влита в `main`, откат
  есть в `backup-history-works` и на GitHub.
- Комментарии в коде — по-русски, в том же стиле, что уже есть: сначала
  «зачем», потом «как».
