### Замер: 300 сообщений + 32 картинки + гифка + 189 каналов

`cargo test --release -- --ignored --nocapture memcheck`

| Что | Было | Стало |
|---|---|---|
| Пол (пустой клиент + кадр) | 9.2 МБ | 9.7 МБ |
| Разбор 300 сообщений: пик | 5.64 МБ / 52 216 | **0.54 МБ / 4 517** |
| Сообщения в памяти | 2.62 МБ | 0.44 МБ (6×) |
| Кэш картинок | 216.00 МБ | 47.25 МБ (4.6×) |
| Кэш с гифкой | 237.38 МБ | 48.00 МБ (4.9×) |
| 10 кадров (чат + списки) | 133 612 аллокаций | 112 534 |
| — только чат (300 сообщений) | 111 276 | 95 929* |
| — только списки (189 + 60) | 19 790 | 14 080 |
| RSS процесса | 255.2 МБ | 84.9 МБ (3.0×) |
| Всего аллокаций за тест | 384 539 | 294 701 (−23%) |

\* из них ~11 700 — новая подпись «не удалось загрузить» для 600 картинок,
которые в замере заведомо битые; без неё чат даёт ~84 300 (−24%).

**Вывод из замера:** «пол» — 9.7 МБ, сообщения — 0.44 МБ, кэш картинок —
48 МБ. То есть **93% памяти клиента — это кэш картинок**, и только он имеет
смысл ужимать дальше.

## Отклонено (проверено, выигрыш не стоит усилий)

- [ ] **`u64` вместо `String` в id.** Экономия ~35 КБ на 300 сообщений
      (8% занимаемой сообщениями памяти), а трогает гейтвей, приложение и
      все экраны: id ходят в URL, в ключи карт, в сравнения.
- [ ] **`Arc<str>` для имён и контента.** Имена повторяются (30 авторов на
      300 сообщений) — выигрыш около 10 КБ. Помогает не памяти, а CPU, и
      тот клон убран вместе с клонами на кадр.
- [ ] **Два размера аватарок (32 и 64).** Кэш аватарок и так ограничен
      8 МБ, весь выигрыш — не больше 3 МБ.
- [ ] **Хеш вместо полных URL в `failed_images`.** Экономия 50 КБ, риск
      коллизий.
- [ ] **`MAX_MESSAGES_PER_CHANNEL` 300 → 150.** Выигрыш 200 КБ, история
      в канале станет короче вдвое.
- [ ] **`u64`-хеш для `pending_images`** — то же самое, что и `failed_images`.
- [ ] **Чистить кэш картинок при смене канала.** Экономия — те самые 48 МБ,
      но все картинки канала придётся качать заново при возврате.
- [ ] **Кэшировать текст (Galley) для сообщений.** Оставшиеся ~9 600
      аллокаций на кадр — это в основном сам egui (вёрстка и шрифт для
      каждого лейбла), а не наш код. Чтобы это убрать, надо писать свои
      виджеты вместо `ui.label`; выигрыш — CPU, не память.
